# Kichray WeaponLab 0.2.0

Отдельная программа на базе восстановленных исходников Material Lab 0.13.0.
Версия 0.2.0 добавляет лабораторию стрельбы по исходникам `kichray/master`.
Предназначена для распакованной gamedata «Тени Чернобыля», прежде всего 1.0006:
список оружия, просмотр world-моделей, правка LTX/XML и создание иконок.

## Начало работы

Сборка: `Kichray_WeaponLab.sln` → Visual Studio 2022 → Release / x64.
Подробная инструкция — `BUILD_RU.md`. Готовый результат:
`bin/Release/x64/WeaponLab.exe` и расположенный рядом `assets/Preview.hlsl`.

При первом запуске открывается окно «Источники WeaponLab».

1. Укажите папку `gamedata`. Можно вставить и путь `gamedata/config/weapons`,
   затем нажать «Использовать стандартные файлы этой gamedata».
2. Стандартные пути:
   - конфиги: `gamedata/config/weapons`;
   - тексты: `gamedata/config/text/rus/string_table_enc_weapons.xml`;
   - иконки: `gamedata/textures/ui/ui_icon_equipment.dds`;
   - модели: `gamedata/meshes`;
   - текстуры: `gamedata/textures`.
3. Любой путь можно заменить своим независимо от остальных. Нажмите
   «Применить пути и прочитать оружие».
4. Выберите оружие слева. Название берётся по `inv_name` из XML, а world-модель —
   из `visual` основной секции. HUD-модели исключаются из каталога.
   Текстуры diffuse/bump/bump# и метаданные THM определяются по материалам OGF.
5. Кнопка «Источники…» позволяет изменить пути в любой момент. Выбор сохраняется
   в `%LOCALAPPDATA%/KichRay/WeaponLab/WeaponLab.ini` между запусками.

Нужны распакованные файлы: архивы игры `.db*` программа не читает. Если XML,
атлас или папка оружия не найдены, окно источников показывает ошибку.
Если OGF/текстуры отсутствуют, путь и ошибка видны в интерфейсе; отсутствующая
текстура обозначается шахматной заглушкой. Предыдущая модель не выдаётся за новую.

## Конфиги и тексты

Читаются `.ltx` во вложенных папках weapons, их `#include` и наследование секций.
При наличии `config/system.ltx` он используется для общих родительских секций.
В каталог попадают секции `wpn_*` либо классы `WP_*` с признаками предмета;
служебные HUD-секции исключены. Поиск работает по названию и имени секции.

Вкладка «Параметры» показывает эффективные значения, включая наследованные.
Числа и числовые векторы получают дискретные ползунки. Под каждым параметром
можно ввести шаг, раскрыть и задать границы диапазона. Колёсико над ползунком
изменяет значение на одну ступень в обе стороны и не прокручивает панель.
Вне ползунка колесо прокручивает список обычным образом. Точное строковое значение доступно под ним.
Границы ползунков — удобство редактирования, а не проверенные игровые пределы.
Неизвестные/строковые значения остаются текстовыми полями.

Изменение наследованного параметра создаёт локальное переопределение в выбранной
секции, не меняя её родителя. Комментарии, порядок строк, окончания строк и
кодировка файла сохраняются. Поддерживаются Windows-1251, UTF-8 и UTF-8 BOM;
ASCII LTX без BOM считается Windows-1251. Новые символы, не представимые в
исходной кодировке, отклоняются с пояснением. Неоднозначные дубликаты блокируют
правку соответствующей секции.

Длинное описание переносится по ширине редактора без изменения текста XML.
Вкладка «Тексты» меняет название по `inv_name` и описание по `description` в
выбранном XML. ID видны рядом с полями. Если ID общий для нескольких предметов,
новый текст будет общим. При отсутствии ID в XML он создаётся. Если самого
`inv_name`/`description` нет в конфиге, сначала задайте ID во вкладке параметров.
`inv_name_short`, если используется отдельный ID, остаётся самостоятельной
ссылкой конфига; отдельного редактора краткого названия в этой версии нет.

## Камера и свет

Математика рендера, навигации и исправление залипающего полёта перенесены из
Material Lab 0.13.0. Renderer, шейдер, иконка приложения и изображение сплэша
сохранены побайтово. Добавлены направления центрирования −X, −Y, −Z к +X, +Y, +Z.

- FLY: WASD, Q/E; Shift быстрее, Ctrl медленнее; ПКМ — обзор.
- ORB: вращение камеры вокруг точки интереса.
- PAN: ЛКМ — сдвиг; средняя кнопка мыши сдвигает камеру во всех режимах.
- LIGHT: ЛКМ — направление света.
- MODEL: ЛКМ — вращение модели.
- ПКМ во всех режимах управляет камерой; колёсико — приближение/удаление.
- F или «Вписать» — вписать модель, Home — сбросить вид.

При смене оружия камера, свет и поворот модели сохраняются.
Во вкладке «Сцена» список частей OGF позволяет временно скрыть дополнительные
меши. Скрытые части не попадают в icon_snapshot; исходный OGF не меняется.
Во вкладке «Сцена» и редакторе иконки можно полностью выключить направленный свет
и оставить ambient/окружение. Свет не меняет файлы материалов. Редактор материалов,
кисти, генерация bump, слои, пресеты и сеансы Material Lab удалены.

## Выбор и создание иконки

Кнопка «Редактор иконки…» открывает отдельное перемещаемое окно внутри приложения.
Его можно свернуть, чтобы расположить модель в основном окне.

Сетка использует настоящие ячейки ТЧ **50×50 пикселей независимо от размера DDS**.
Это не деление размера изображения на 20. Атлас 1024×1024 имеет 20×20 полных
клеток, 2048×2048 — 40×40, 4096×2048 — 81×40. Координаты за пределами первых
20 клеток доступны прокруткой. Остаток справа/снизу сохраняется без растягивания
или добавления неполной клетки. Зум меняет лишь отображение, а не координаты.
Предел загрузчика: 16384 пикселя по стороне, до 16 мегапикселей в сумме.

**Выбрать существующую иконку:** щёлкните по клетке или протяните прямоугольник
ЛКМ. X/Y и ширину/высоту можно ввести численно. Кнопка «Выбрать эту иконку для
оружия» меняет `inv_grid_x`, `inv_grid_y`, `inv_grid_width`, `inv_grid_height`.
Это ещё не запись файла — нажмите общую кнопку «Сохранить».

**Создать новую иконку:**

1. Расположите модель; выберите вид и освещение. При желании выключите
   направленный свет полностью.
2. Задайте размер и положение иконки в сетке.
3. Нажмите «Сделать icon_snapshot».
4. Программа снимет модель на прозрачном фоне, исключив UI и вспомогательные
   линии. Большая сторона исходного снимка не превышает 1024 пикселей.
5. Видимые пиксели вписываются в размер выбранных клеток без растяжения.
   Фон обрезается по альфе; поле вокруг модели задаётся в пикселях.
   При изменении выделения предпросмотр пересчитывается из исходного снимка.
6. Нажмите «Вставить снимок в выделение». Занятые клетки требуют подтверждения.
   Программа перечисляет пересекающиеся иконки оружия; предметы вне каталога
   weapons также могут использовать эти клетки.
7. Нажмите общую кнопку «Сохранить» — она сохраняет DDS и изменения LTX/XML.
   Снимок можно дополнительно вывести в отдельный прозрачный PNG.

Вставка заменяет весь выбранный прямоугольник, включая прозрачные пиксели.
Все декодированные пиксели вне него сохраняются. Чтобы не пересжимать соседние
иконки, DDS записывается в несжатом legacy A8R8G8B8 (RGBA32), один mip-уровень.
Атлас 1024×1024 после сохранения занимает примерно 4 МиБ. Исходный DDS остаётся
в резервной копии. Формат совместим с загрузчиком DDS, но его отображение в вашей
конкретной сборке игры пока не проверено запуском.

## Лаборатория стрельбы

При выборе параметра, относящегося к стрельбе или износу, вместо модели
открывается лабораторная диаграмма. Можно вернуться к модели отдельной кнопкой.
Симуляция предназначена только для поддерживаемых огнестрельных классов;
патроны, ручные гранаты, ножи и гранатомёты не получают ложную пулевую модель.

Параметры оружия берутся из текущей редактируемой секции. Боеприпас выбирается
из её `ammo_class`, а значения патронов — из загруженных LTX, включая обычный
`gamedata/config/weapons/weapons.ltx`. Отсутствующие секции и обязательные
настройки отмечаются как недоступные, а не заменяются вымышленными данными.

- Разброс: лабораторная мишень на дистанции 10–100 м с фиксированным
  масштабом мишени в сантиметрах, чтобы изменение конуса было видно при движении ползунка.
- Траектория: падение относительно линии выстрела на дистанции 100–300 м.
- Износ: расход состояния за выстрел и полный магазин, расчёт выстрелов и
  магазинов до состояния 0. Это теоретическая характеристика износа: состояние 0
  само по себе не запрещает выстрел в движке. Осечки имеют отдельную игровую
  вероятность; число до 0 не означает гарантированную работу без задержек.
- Подписи параметров объясняют направление изменения и участие в модели.

Стенд держит ствол неподвижно: движения игрока, поза, отдача камеры,
глушитель и столкновения не моделируются. RPM задаёт интервалы выстрелов;
без движения ствола он сам по себе не расширяет конус разброса. Режим стрельбы
также влияет на износ при включённом `preffered_fire_mode`.

Формулы сверены с `BCZUnofficial/kichray`, ветка master, ревизия
`6d832035330a004a2ffabce8d124f17409dcc563`. Условия стенда, точные переносимые
алгоритмы и ограничения перечислены в `docs/BALLISTICS_MODEL_RU.md`.
Это расчёты игрового движка, не физическая модель реального оружия.

## Сохранение

Правки сначала находятся в памяти. Переключение оружия не теряет уже принятые
правки. Непринятое некорректное значение нельзя молча потерять при сохранении
или смене оружия. При закрытии/смене источников предлагается сохранить,
отбросить или отменить переход.

«Сохранить» / Ctrl+S сохраняет все изменённые файлы, в том числе при фокусе
в поле описания или точного значения. «Сохранить DDS-атлас» в окне иконок
записывает только DDS; координаты в LTX нужно сохранить общей кнопкой.
«Отменить правки» перечитывает LTX/XML с диска; отмена атласа отдельная.

Перед заменой создаются нумерованные резервные копии `*.weaponlab.bak.*` рядом
с оригиналами. Если файл изменён другой программой после загрузки, сохранение
отклоняется. Чтобы восстановиться, закройте WeaponLab и скопируйте нужный backup
на исходное имя. Запись каждого файла выполняется через временный файл и замену;
единой транзакции DDS+LTX+XML при отключении питания нет. Если сохранение DDS
успело завершиться, а LTX/XML завершилось ошибкой, сообщение это явно указывает.

## Проверки и границы этой поставки

Это **исходники для сборки**, не проверенный нативным запуском Windows-релиз.
Подробности — `verification/BUILD_STATUS_RU.txt` и журналы рядом.
Переносимые тесты проверяют LTX/XML, кодировки, точечные правки и конфликты,
атлас и прозрачность, OGF/DDS, камеру, ступенчатые контролы и компоновку UI.
Интерфейс осмотрен через CPU-растеризацию draw data ImGui с тестовыми текстурами.

MSVC/Windows SDK, нативный D3D11/WARP, WIC PNG и работа на вашей gamedata в этой
среде не проверены. Для Windows включён `WeaponLab.exe --smoke-test`: он проверяет
D3D/WARP и PNG на синтетическом меше, не редактируя вашу gamedata. Реальные
модели/конфиги/атлас пользователя не приложены; `sie.exe` не запускался и его код
не копировался. Погодное окружение/постобработка игры по-прежнему не загружаются.

Первичные ссылки по сетке и конфигам приведены в `BUILD_RU.md`.
